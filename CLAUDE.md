# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

Career Intelligence Assistant: upload a resume and job postings, then chat about fit, skill gaps, experience alignment and interview prep. See `README.md` for the spec and design notes.

Two independent pnpm packages with no root workspace. Run commands from inside each directory.

- `backend/`: TypeScript API on Hono, with SQLite via Drizzle ORM. Basic Auth protects the API. Users keep libraries of CVs and job postings (text is extracted from uploads) and every chat is tied to one CV and one or more numbered jobs; these go into the system prompt, whose text is a versioned markdown file chosen by a small config file (each reply records the version that produced it). Replies are generated by a remote Ollama API through the Vercel AI SDK and streamed to the client. OpenAPI docs (Swagger UI) are served by the backend. Environment is read once into a config object; external dependencies (Ollama, file text extraction) are service classes handed to routes through a small middleware, so routes never read env or build clients and tests can pass fakes into the app factory.
- `frontend/`: Vite + React + TypeScript chat UI. Built with shadcn/ui (Base UI flavour), Tailwind, TanStack Query and AI Elements chat components. In dev, Vite proxies API calls to the backend so the browser sees one origin and its own Basic Auth prompt works (the frontend holds no credentials); a typed client shares types with the backend.

The frontend imports types from the backend, so keep shared dependencies (notably `hono`) on the same version in both packages.

## Commands

Backend (`cd backend`):
- `pnpm dev`: run with file watching
- `pnpm build` / `pnpm start`: compile and run the build
- `pnpm db:generate --name <name>`: create a migration after changing the schema
- `pnpm db:migrate`: apply migrations manually (they also run on server startup)
- `pnpm test`: run the backend tests (vitest). They build the real app with a scripted fake model and an in-memory database, so they need no network, ports or `.env`. `pnpm test:watch` re-runs on change
- `PORT=3111 DATABASE_URL=/tmp/test.db pnpm dev`: run a second instance without touching a running dev server or its database

Frontend (`cd frontend`):
- `pnpm dev`: dev server
- `pnpm build`: typecheck and build
- `pnpm lint`
- `pnpm dlx shadcn@latest add <component>`: add a UI component
- `pnpm dlx ai-elements@latest add <component>`: add an AI Elements component

Setup: in `backend/`, copy `.env.example` to `.env` and fill in the values (credentials, Ollama URL, model and API key). `.env` files are git-ignored. The frontend needs no `.env`; the browser prompts for the backend credentials. Restart the dev server after editing `.env`.

Tests exist for the backend only (vitest); the frontend has none yet.

## Lessons learned

- Use pnpm, not npm. The lockfiles are pnpm, and some template READMEs still say npm.
- The frontend type-checks the backend files it imports types from, so backend code must also satisfy the frontend's stricter TypeScript settings (for example no constructor parameter properties).
- Generated files can be wrong for this stack. AI Elements assumes Radix but the project uses Base UI, so vendored files may need small patches. Note any hand edit so it survives regeneration.
- To change the chat prompt, add a new version file under `backend/prompts/` and point `backend/config/prompts.json` at it, rather than editing an existing version (see `backend/prompts/README.md`)
